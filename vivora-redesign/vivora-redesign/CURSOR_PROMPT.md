# مهمة: دمج تطوير الصفحة الرئيسية لـ Vivora في المشروع الأصلي وإكمال بقية الأقسام

## السياق
المشروع الأصلي (موجود عندك في الـworkspace) هو موقع Vivora للعناية بالبشرة: Next.js (App Router) + Tailwind + TypeScript، الصفحة موبايل بعرض أقصى 430px، وفيه الأصول الحقيقية (hero.mp4, sam.mp4, 2.jpg, 3.jpg, 4.jpg, vivora.beauty.jpg, vivora.beauty.official-20260620-000x.jpg).

تم تطوير نسخة أولى في مجلد منفصل `vivora-redesign/` (الملفات المرفقة). هذه النسخة تغطي فقط: `app/page.tsx`، `components/Hero.tsx`، `components/SiteHeader.tsx` (جديد)، `app/layout.tsx`، `app/globals.css`، `tailwind.config.ts`، وخطوط محلية في `app/fonts/`. الأقسام الأخرى لم يتغير تصميمها.

الهوية: ألوان ترابية دافئة (tokens في `src/styles/tokens.css` و`vivora-*` في Tailwind)، العناوين Cormorant Garamond، النص DM Sans. لا تغيّر الألوان ولا الخطوط ولا تضف لوناً جديداً بلا دور واضح.

## الخطوة 1: الدمج (قبل أي تطوير)
1. افحص المشروع الأصلي أولاً: package.json، app/، components/، public/، وأي اختلاف عن الملفات المرفقة.
2. قارن كل ملف مرفق مع نظيره في المشروع الأصلي (diff) ثم ادمج، لا تستبدل بالجملة:
   - `app/page.tsx`: يضيف `SiteHeader` وskip link وغلافات الـanchors (`#story`, `#bundles`, `#contact`) مع الحفاظ على ترتيب الأقسام. `ProductsSection` يحمل `id="products"` أصلاً.
   - `components/Hero.tsx`: النسخة الجديدة بدون state للتحميل: حركة CSS (`.hero-rise`, `.hero-settle`)، الـh1 هو عنوان الـHero (الشعار انتقل للهيدر)، الفيديو يتوقف مع reduced-motion، والـposter هو `/hero-poster.jpg`.
   - `components/SiteHeader.tsx`: ملف جديد (هيدر ثابت، قائمة `<dialog>` أصلية، يختفي عند النزول).
   - `app/layout.tsx`: خطوط محلية عبر `next/font/local` بدل `<link>` لـGoogle Fonts، وإزالة `maximumScale: 1` (يمنع الزووم). انسخ مجلد `app/fonts/` كاملاً. إذا كان بيئتك متصلة بالإنترنت يمكنك استبدالها بـ`next/font/google` بنفس أسماء المتغيرات: `--font-cormorant`, `--font-dm`, `--font-inter`, `--font-montserrat`.
   - `app/globals.css`: ادمج الإضافات (skip link، `:focus-visible`، keyframes الـHero والقائمة، `.anchor-section`، قاعدة `prefers-reduced-motion`) مع القديم دون تكرار. احذف تعريفات `--font-cormorant`/`--font-inter` النصية القديمة لأن `next/font` يعرّفها الآن.
   - `tailwind.config.ts`: فقط `fontFamily.display` و`fontFamily.sans` صارا يشيران إلى `var(--font-cormorant)` و`var(--font-dm)`.
3. لا تستبدل أي صورة أو فيديو حقيقي. أي صورة باسم `PLACEHOLDER` هي مؤقتة في نسخة الاختبار فقط ولا تُنسخ.
4. لا تحذف ميزة تعمل. إذا وجدت سلة أو منطق شراء في المشروع الأصلي، اربط به زر الحقيبة في الهيدر بدل أن يكتفي بالانتقال إلى `#products`.
5. شغّل `npm run build` بعد الدمج وأصلح أي خطأ قبل المتابعة.

## الخطوة 2: إكمال تطوير بقية الأقسام (بالترتيب، قسم قسم)
حافظ على الترتيب: Hero → Brand → Products → Ingredients → Journal(Bundles) → Instagram → Newsletter → Footer. ابدأ بـProducts لأنه الأقرب للبيع.

المشاكل المعروفة التي يجب معالجتها:
- **ProductsSection**: كروت بزوايا مدورة وظل مزيف وتوهج وميلان 3D (`rotateX/Y`) وشارات صغيرة؛ نصوص 8–11px؛ زر الحقيبة داخل الكرت ليس زراً فعلياً (span بلا وظيفة)؛ السهم `ArrowButton` بلا رابط؛ الكروت لا تعمل بالكيبورد. المطلوب: كرت أبسط يجعل المنتج هو البطل، السعر واضح، نص لا يقل عن 12px، زر إضافة حقيقي أو رابط حقيقي، تمرير أفقي يعمل بالمس والكيبورد مع أزرار تحكم ظاهرة.
- **BrandSection / DecorativeArc**: scroll listener يستدعي `setState` في كل إطار؛ استبدله بـIntersectionObserver أو CSS (`animation-timeline: view()` مع fallback)، وتحريك transform/opacity فقط، وإزالة blur المتحرك. شكل الصورة العضوي (`rounded-[60%_40%...]`) يحتاج قراراً فنياً: إما يبقى كتوقيع بصري متسق أو يُستبدل بقص نظيف.
- **JournalSection (Bundles)**: بطاقات بيضاء مدورة بظل وتوهج؛ شارات مثل "Limited Offer / Best Seller / New Drop" **ادعاءات تسويقية غير مؤكدة** يجب أن تُحذف أو تُستبدل بمعلومات حقيقية يؤكدها صاحب المشروع؛ الأزرار بلا وظيفة (`<button>` بلا href)؛ نصوص 8–10px.
- **InstagramSection**: زر "Follow Us" بلا رابط حقيقي؛ `<p>` فارغ؛ نصوص صغيرة؛ سؤال: هل توجد صور إنستغرام حقيقية؟ إن لم توجد فلا تكرر نفس الصورة كأنها بوست.
- **IngredientsSection**: الفيديو بنسبة 9/16 كبير جداً على الشاشات القصيرة؛ `styled-jsx` للحركة (انقلها لـglobals أو CSS module)؛ حركة بتأخير حتى 1.8 ثانية تؤخر ظهور المحتوى؛ الاسم "Samar Alrashed" وجملة "Only proven ingredients" ادعاء يجب التأكد منه قبل إبقائه.
- **NewsletterSection**: لا يوجد حقل بريد إلكتروني إطلاقاً (زر أيقونة فقط)؛ المطلوب نموذج حقيقي: label ظاهر، input من نوع email، رسائل نجاح وخطأ، وlive region. إذا لا يوجد backend فاترك الإرسال مفصولاً بدالة واضحة واكتب في التقرير أنه غير موصول، ولا تُظهر نجاحاً وهمياً.
- **SiteFooter**: كل الروابط `href="#"`؛ اربطها بصفحات أو anchors حقيقية أو أزلها؛ تأثير الـunderline لا يعمل (يعتمد على `group-hover` بدون `group`)؛ نصوص 10–11px بتباين منخفض (`#9a9a9a` على أبيض)؛ ثلاثة أعمدة ضيقة جداً عند 320px.
- **عام**: استبدل ألوان hex المتفرقة (`#3a3a3a`, `#efefef`, `#1f1f1f`…) بـtokens (`vivora-*`)؛ وحّد أسلوب الأقسام (الآن: خلفيات رمادي/أبيض/أسود تكسر الهوية الترابية)؛ وحّد أنماط الأزرار والشارات في مكونات مشتركة صغيرة؛ استبدل الإيموجي بـSVG؛ كل ما يُنقر لا يقل عن 44×44px.

## قواعد لا تُكسر
- لا تخترع أسعاراً أو مراجعات أو شهادات أو مكونات أو ادعاءات طبية أو أرقام عملاء أو حالة مخزون. الأسعار الحالية (₪100، ₪100، ₪110) موجودة في الكود الأصلي فقط، لا تغيّرها.
- لا تغيّر الإطار ولا تضف مكتبات بلا ضرورة. الحركة بـCSS أولاً، وtransform/opacity فقط، واحترم `prefers-reduced-motion`.
- لا تعطّل الزووم، ولا تكسر الـSSR/hydration، ولا تترك أخطاء console.
- لا تعدّل منطق الدفع أو المخزون أو الطلبات أو المصادقة إن وُجدت.
- لا تقل إن اختباراً نجح إلا إذا شغّلته فعلاً ونجح.

## التحقق بعد كل قسم
`npm run build` و`npx tsc --noEmit` (وlint إن وُجد في scripts)، ثم افحص بمتصفح فعلي عند 320 / 390 / 430 / 768 / 1280 / 1920: لا تمرير أفقي، لا نص مقصوص، لا أخطاء console، التنقل بلوحة المفاتيح، القائمة، التمرير الأفقي للمنتجات، ووضع reduced-motion.

## التقرير النهائي (مختصر وصادق)
ما تغيّر، الملفات الرئيسية، الأوامر التي شغّلتها ونتيجتها الفعلية، وما بقي غير مكتمل (أصول ناقصة، backend غير موصول، ادعاءات تحتاج تأكيد صاحب المشروع).
